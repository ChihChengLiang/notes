**Q2 (7 votes):** "Will PC allow smart contracts to have signing functionality similar to EOAs?"

**Vitalik:** It depends what you want out of "signing functionality." If you just want the ability to express authority, you don't need any programmable cryptography — you can just use Ethereum's built-in call mechanism. The interesting thing obfuscation gives you is a SNARK whose verification algorithm is literally "verify any kind of signature scheme" — at the cost of requiring a trusted setup — meaning you get zero-knowledge proofs that are only as expensive as a signature, which is extremely cheap today (the quantum-resistant versions are somewhat more expensive, but still interesting). The harder version is encryption rather than signing: what if you want a program with a secret that it releases under smart-contract conditions? You'd have an obfuscated program that releases the secret if given a proof of blockchain consensus — some finalized root showing a particular condition was met — and only then outputs the secret. The challenge is vulnerability to a 51% attack: if 51% of stakers collude, they can privately extract the secret without ever being slashed. One mitigation is adding a small amount of proof-of-work — say 1% — so extracting the secret costs at least a few million dollars per attempt. So: possible, but with caveats, which I think is interesting.
